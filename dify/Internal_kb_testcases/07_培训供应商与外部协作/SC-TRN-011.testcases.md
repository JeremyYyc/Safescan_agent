# SC-TRN-011 测试用例（质量审计、神秘访客与整改闭环）

> 被测文档：dify/Internal_kb/07_培训供应商与外部协作/SC-TRN-011_质量审计神秘访客与整改闭环.md

## 用例 1 —— 双层审计体系定位

- **case_id**: TC-SC-TRN-011-01
- **类型**: retrieval（信息定位）
- **难度**: 易
- **问题**（员工/住户的真实问法，中文，可含州名/业务线/编号术语）:
  > 我们站点多久要做一次自审？集团多久来抽审一次？
- **期望召回文档**: SC-TRN-011
- **期望锚点（章节）**: 「## 2. 审计体系与治理」
- **回答必须覆盖/包含的要点**:
  - 站点月度自审由各站点 Property Manager 牵头，组织本站点相关岗位按审计清单对各维度做一次自查
  - 集团季度抽审由集团质量与合规审计组执行，在各州站点中按一定比例抽样，做独立、跨职能的深度核查
  - 对"下住学生、上住长租"或同楼分层的站点，集团抽审与站点自审均须按楼宇分区分别执行
  - 审计组成员不应来自被审计站点自身，以确保客观性与独立性
- **不应出现/不应编造**: 不得编造法定审计频率；不得声称审计为法规要求；不得引用不存在的文档编号
- **验收方式**: 检索应命中 SC-TRN-011 的「## 2. 审计体系与治理」；回答可引用「SC-TRN-011 §2」并覆盖要点；不得引用不相关文档。

## 用例 2 —— 神秘访客/神秘住户评估范围与边界

- **case_id**: TC-SC-TRN-011-02
- **类型**: boundary（边界/例外/不适用）
- **难度**: 中
- **问题**（员工/住户的真实问法，中文，可含州名/业务线/编号术语）:
  > 集团会不会派人假扮住户来体验？这种评估适合放在哪条线？能进住户房间吗？
- **期望召回文档**: SC-TRN-011
- **期望锚点（章节）**: 「## 4. 神秘访客/神秘住户评估」
- **回答必须覆盖/包含的要点**:
  - 神秘访客（Mystery Shopper）或神秘住户（Mystery Resident）评估以学生线（PBSA）为主且为可选机制
  - 评估并非每次审计都必须，由集团按风险、站点表现与预算决定
  - 对涉及公寓内部或住户私密区域的，须按进房权与隐私边界将评估限制在公共区域与合规允许的范围内
  - 评估报告应客观、基于事实，涉及个人信息或敏感观察的按隐私与最小化原则处理
- **不应出现/不应编造**: 不得编造户籍/身份证明要求；不得声称可进入住户私密空间；不得引用不存在的文档编号
- **验收方式**: 检索应命中 SC-TRN-011 的「## 4. 神秘访客/神秘住户评估」；回答应说明以学生线为主、为可选机制、且受进房权与隐私边界约束；不得引用不相关文档作为主依据。

## 用例 3 —— 问题分级整改时限与闭环验证

- **case_id**: TC-SC-TRN-011-03
- **类型**: process_qa（流程步骤） + cross_doc（跨文档协作）
- **难度**: 中
- **问题**（员工/住户的真实问法，中文，可含州名/业务线/编号术语）:
  > 审计发现我们清洁不达标，属哪一级问题、要多久整改？怎么才算整改真正闭环？
- **期望召回文档**: SC-TRN-011（另需 SC-TRN-007）
- **期望锚点（章节）**: 「## 6. 问题分级与整改时限」与「## 7. 整改闭环与验证」
- **回答必须覆盖/包含的要点**:
  - 问题分三级：一般问题限期整改（内部建议 7 个工作日内）；较高问题限期整改（内部建议 14 个自然日内）；严重问题（涉及安全、火灾、消防、隐私、未成年人保护、歧视或重大合规/法律风险）立即整改并过集团审批
  - 整改闭环：每项整改完成后须进行闭环验证，由整改责任人提交整改证据，复核人确认问题解决、是否引入新风险、是否达到标准
  - 闭环验证强调"避免复发"，应识别根因（是流程缺陷、培训不足、资源不足、供应商能力问题还是标准本身问题）
  - 涉及第三方（如供应商、校方、代理）的问题，整改责任与协作方按对应文档（SC-TRN-007/008/009/010）划分
- **不应出现/不应编造**: 不得编造法定整改时限；不得声称整改时限为法规要求；不得引用不存在的文档编号
- **验收方式**: 检索应命中 SC-TRN-011 的「## 6. 问题分级与整改时限」与「## 7. 整改闭环与验证」；回答应引用「SC-TRN-011 §6/§7」并可联动「SC-TRN-007」；不得仅引用不相关文档。
