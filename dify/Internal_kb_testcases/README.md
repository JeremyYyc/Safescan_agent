## v1 校验脚本的适用范围

```sh
python3 kb_build/qa_testcases.py
```

从项目根目录执行。命令检查旧用例文件是否存在及每文件用例块数，提取旧字段并重新生成两个旧 manifest；不验证真实问答、事实依据、权限或引用语义，也不完整验证字段和锚点。

脚本仅扫描 `0*/*.testcases.md`，不支持 `scenarios/` 下的 v2 用例。其 `PASS` 不代表 v2 标注通过或 Dify 在线测试成功。

## 新用例如何设计

1. 明确目标：指定文档定位、自然问答、跨文档综合、资料不足或权限边界。
2. 固定语料快照：`emp_only` 只含 EMP 九篇；`internal_full` 须确认 93 篇已实际接入且可检索。本地有文件不等于线上可用。
3. 写明身份、允许的库和适用范围，再定义必答事实、可选细节、预期缺口及禁止项。
4. 每项事实核对证据：替代来源为 OR，联合支持的条款为 AND；所有必答事实必须覆盖。
5. 定位必须命中指定文档/章节；业务问答接受其他适用且获授权的充分证据，不能用“任意相关文档命中”代替事实验收。

旧 `expected_docs` 只作为重新审查证据的起点。按文档归档不代表业务问题只有该文件能回答。

## 执行与验收

逐条保存问题、身份、语料快照、检索设置、实际路由、切片、模型上下文、回答与引用。测试集和参考答案不上传到被测知识库。

分别检查定位、证据覆盖、回答覆盖、依据一致性、引用准确性、缺口处理和访问边界。新发现的来源先人工复核，再更新标注并统一复评。

- 全库可答却漏检：覆盖失败；诚实说明缺口不等于完整问答通过。
- EMP-only 预设缺资料：有据局部回答并说明缺口可通过此类测试，业务完整性仍为 `partial`。
- 未接入要求语料：前置条件不满足，记 `not_applicable`，不能算模型失败或通过。
- 越权、伪造引用或无据补充：不能靠其他得分抵消。

完整字段、模板、独岗示例和评分状态见 [测试规范](../../kb_build/testcase_spec.md)。后续按场景逐批迁移，保留旧编号映射及版本。
