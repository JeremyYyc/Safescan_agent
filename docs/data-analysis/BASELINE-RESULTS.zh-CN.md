| 房型参数填充率 | 5/27，18.52% | 房型层的卧室数、卫浴数、面积；房号面积不向房型自动传播 |
| 报价口径完整率 | 0/8 | 缺计价基础、租期或周期等条件；不进行跨来源价格比较 |
| 图片完整性通过率 | 27/27 | 解码、尺寸、SHA-256 检查通过，不代表内容可读或归属正确 |

| 用途准入率 | N/A，0/0 | 无质量合格样本；两个来源权限均为 unknown |
| 请求成功率、人工耗时 | N/A | 历史日志不足，不补造成功率或零成本 |

“0 条合格”表示尚无满足完整验收标准的样本，不等于原始资料毫无价值，也不证明原网站不存在所缺字段。逐样本缺口见本地 `checks.json`。

HOME 去重后的 13 份图片经助手初步分类：室内 4、公共空间 4、外观 2、宣传 2、户型图 1。户型图当前清晰度不足，暂不算可用核心素材；初步核心素材占比为 4/13（30.77%）。分类是待人工核验的建议，不作为关联准确率或人工审核通过记录。

## 改进与复验

1. 固定两份输入快照和 9 个房型，不通过追加样本改变前后对比分母。
2. 从 HOME 已保存 HTML 的 JSON-LD 提取此前遗漏的地址，身份与位置字段从 53/54 提升到 54/54；没有推测地址或重新抓取。
3. 按图片内容而非 URL 去重，HOME 的 14 条图片记录对应 13 份内容；原记录保留，不物理删除素材。
4. 修复测试发现的 Windows SQLite 连接释放问题。
5. 采集测试 17 项、分析测试 14 项全部通过。两个独立输出目录的 JSON 明细、指标及 Markdown 报告一致。
6. 校验 11 份输出文件哈希、输入快照哈希、SQLite 外键、JSON/SQL 数量及质量结果一致性。

地址修复没有让严格合格率上升；图片去重减少的是重复计数，不是新增可用素材。本轮没有完成交互看板、独立人工审核或发布回滚验收。
